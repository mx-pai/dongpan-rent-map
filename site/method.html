找房需要同时回答两个问题：具体房间是否适合居住，从实际门址到办公楼是否满足通勤时间，地图点位用来定位和测路，租赁及住宿页面用来核对房型、面积、价格与条件，页面把两类信息通过 POI、地址和原始来源关联起来

从公开资料到可筛选的地图

  1. 地点核验高德 POI ID、院号、门店地址
  2. 测量通勤步行、骑行、地铁与分段接驳
  3. 核对租住信息房型、月租、卫浴、押付及来源日期
  4. 发布前校验时长加总、信息状态、静态资源
  5. Actions 发布推送 main 后构建 GitHub Pages

小区优先使用住宅区 POI，酒店和公寓按门店地址核对，同名异店、同楼不同经营者、覆盖多个分区的小区会在点位备注中说明，找到具体房号后应从可出入的大门重新测量

通勤的三种时间口径

直接步行或自行车

住处 → 东畔 A 座

步行 ≤30 分钟
自行车 ≤20 分钟

读取高德路线页面对应的 duration，使用住宅点位或门店坐标计算，范围由已测点位表示

地铁自动全程

住处 → 两端接驳与地铁 → A 座

全程 ≤20 分钟

保留全程规划时长，公共交通方案筛选为地铁，公交及出租车不混入此口径，规划时刻单列在数据中

分段测量

到站接驳 + 入口到出口地铁 + 到楼步行

分段加总 ≤20 分钟

地铁段保留站内步行、换乘和预计等车，比较步行或骑行接驳，页面同时展示按秒合计与各段向上取整后的分钟合计

按用户最初的“地铁乘车20分钟”口径，页面还可以筛选地铁线路段 ≤20 分钟的点位，此时间取地铁线路的运行时长之和，接驳时间另列，申请时应上传地图 App 各测距方式页面截图，以各段页面显示的时长相加为准

慧忠北里分段实例

骑行到安立路 A1 口 222秒 + 地铁入口到北沙滩 A 西北口 627秒 + 步行到 A 座 229秒 = 1078秒，约18.0分钟，各段分别向上取整后为4 + 11 + 4 = 19分钟

房型、费用与信息日期

每条房源样本分别保存出租方式、户型、面积、卫浴、厨房、月租、押付、附加费用及原始链接，住宅合租的房间面积与多人住宿的整间面积分别标注，整租和合租的价格在详情中分开显示

能读取完整页面的资料标为“已读取来源页面”，搜索引擎缓存标为“搜索抓取文本”，已标注历史代理、过时优惠的房源保留为历史样本，当前房态未获门店或发布者确认，页面不把日租报价换算成包月价格

在本机复现与更新

网页由 HTML、CSS、JavaScript 与一份 JSON 数据组成，打开页面时读取已发布快照，API key 供本机或 GitHub Actions 的路线重算脚本使用，仓库提供 POI、天气和路径查询 CLI，高德官方 MCP 可以把相同能力作为工具接入支持 MCP 的客户端

git clone https://github.com/mx-pai/dongpan-rent-map.git
cd dongpan-rent-map
python3 scripts/validate.py
python3 scripts/build.py
python3 -m http.server 8000 --directory _site

需要重新测路时，设置环境变量 AMAP_API_KEY，执行 python3 scripts/refresh_routes.py --ids 24 可以重算某个点位，--max-points 0 表示重算所选全部点位，公共房源信息由人工核对原页面后，通过证据导入脚本更新，路线重算保留房源证据

仓库的 Pages 工作流 在 main 分支推送后校验数据、构建静态页面、上传产物并部署，另有手动路线测量工作流，使用仓库 Secret AMAP_API_KEY，产出可下载 JSON 供核对后提交，房源信息日期与路线测量日期分别保留
